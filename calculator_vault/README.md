# Calculator Vault

A premium, cross-platform Flutter application. On the surface: a beautiful,
fully functional calculator. Underneath: a completely offline, AES-256
encrypted personal vault for photos, videos, documents, notes and passwords,
unlocked by entering a secret PIN followed by `=`.

## Tech stack

- Flutter (latest stable) / Dart 3
- Riverpod (state), GoRouter (navigation)
- Hive CE (local, non-sensitive data), flutter_secure_storage (secrets)
- `cryptography` (AES-256-GCM), `local_auth` (biometrics)
- flutter_animate / animations / lottie, Google Fonts, Material Symbols

## Getting started

The repository ships the `lib/`, `test/`, and config files. Platform folders
are generated locally so they always match your installed Flutter version:

```bash
cd calculator_vault
flutter create . --platforms=android,ios --org com.codebysushant
flutter pub get
flutter run
```

After every phase:

```bash
dart format .
flutter analyze
flutter test
```

## Architecture

Clean Architecture + MVVM, feature-first:

```
lib/
  core/          # constants, errors, router, services, utils
  shared/        # theme (colors, typography, ThemeData)
  features/
    splash/
    calculator/
    # later phases: authentication/ vault/ photos/ videos/
    # documents/ notes/ passwords/ settings/
  app.dart       # root widget, theming, dynamic color
  main.dart      # bootstrap (Hive init, error hooks)
```

Rules:

- Secrets (PIN hash, salt, master key) live only in secure storage.
- Hive holds non-sensitive settings and encrypted-at-rest metadata.
- All navigation goes through `AppRoutes`; no raw route strings.
- All user-visible errors derive from `AppException` subclasses.

Known scoping (by design, per the phase plan):

- Category screens show fully working metadata lists (sort, select, rename,
  pin, favorite, trash); the type-specific import flows and viewers land in
  Phases 7–11.
- Calculator history stores math only; pure digit entries (potential PIN
  attempts) are never written to history.
- Platform folders are generated by `flutter create .` rather than
  committed. After generating, copy `platform/android/MainActivity.kt` in —
  see `platform/README.md` (required for FLAG_SECURE).
- iOS cannot block a foreground user screenshot (platform restriction, all
  apps); the app switcher preview IS covered via the PrivacyShield.
- Photo import uses the system Photo Picker (no media permission). Removing
  the original from the *device* gallery is intentionally not done — the
  picker grants no delete rights and requesting full media management would
  defeat a discreet vault. Imported copies are encrypted; the picker's temp
  copy is deleted.

Auth flow summary: first launch → PIN setup (create → confirm → biometric
opt-in → one-time recovery key). After that: PIN + `=` in the calculator
unlocks; backgrounding or 60s idle re-locks; the lock screen offers PIN,
biometrics, and recovery-key PIN reset, with a 5-attempt / 30s cooldown.
The lock screen can only appear mid-session — a cold start always boots to
the plain calculator.

## Security model (summary)

- Vault content encrypted with AES-256-GCM. Envelope encryption: every file
  gets a fresh random 256-bit data key, wrapped by the master key. Files are
  encrypted in 1 MiB chunks (bounded memory for any file size) inside a
  background isolate; per-chunk nonces derive from a random prefix + chunk
  index, so reordering, substitution, tampering and truncation are all
  detected on decrypt.
- The master key is generated from a CSPRNG at setup and lives only in
  platform secure storage (Android Keystore-encrypted prefs / iOS Keychain).
  The PIN acts as access control; this keeps forgot-PIN recovery lossless.
- PIN and recovery key are never stored — only salted PBKDF2 hashes.
- Decrypted temp files (video playback, sharing) are wiped the moment the
  session leaves the unlocked state, and again on every app start.
- FLAG_SECURE is active whenever a vault session exists (unlocked OR
  locked) and during PIN setup, so screenshots are blocked and the recents
  preview is blank on Android; a Dart-side PrivacyShield covers the app
  switcher on both platforms the moment the app resigns active.
- Vault item names and note/password payloads are AES-encrypted inside the
  Hive metadata index; undecryptable entries are skipped, never fatal.
- Trash keeps items 30 days, then auto-purges metadata AND encrypted files.
- Immediate lock on backgrounding; configurable auto-lock timeout.
- Debug logging fully stripped from release builds.

Note: `package:cryptography`'s pure-Dart AES-GCM is correct but not
hardware-accelerated; if large-video import feels slow on device, Phase 14
adds `cryptography_flutter` for native crypto with zero format changes.
